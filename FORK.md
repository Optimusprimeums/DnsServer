# optimusprime-nn DnsServer fork

This fork of [Technitium DNS Server](https://github.com/TechnitiumSoftware/DnsServer) adds:

- redundant DHCP. See [DHCP-FAILOVER.md](DHCP-FAILOVER.md).
- cluster improvements, including 2-node auto failover. See [CLUSTER-IMPROVEMENTS.md](CLUSTER-IMPROVEMENTS.md).
- automatic TLS certificates (ACME, DNS-01) for the web console and encrypted DNS. See [ACME.md](ACME.md).

## How the branches fit together

The features are developed as separate upstream pull requests. This fork's build combines them.

| Branch | Based on | Contains | Purpose |
|---|---|---|---|
| `upstream/dhcp-failover` | `TechnitiumSoftware/develop` | DHCP failover only | Pull request to upstream |
| `upstream/cluster-improvements` | `TechnitiumSoftware/develop` | Cluster improvements only | Pull request to upstream |
| `upstream/acme` | `TechnitiumSoftware/develop` | ACME certificates only | Pull request to upstream |
| `fork/main` | latest upstream release (`master`) | all three features, plus fork-only additions | What CI builds and the installer ships |

The upstream branches don't depend on each other and merge cleanly in any order. `fork/main` carries the same feature commits, cherry-picked onto the release. Its fork-only additions are:

- CI, including the ACME end-to-end test against Pebble (`.github/acme-e2e/run.sh`), which must pass before a release is published;
- the installer and release publishing;
- fork version numbers and the update feed;
- the DHCP failover state shown in the Cluster node table, which needs both features.

To change a feature, commit to its `upstream/*` branch and cherry-pick the commit onto `fork/main`.

## Install or update (Linux, systemd or OpenRC)

```
curl -sSL https://github.com/optimusprime-nn/DnsServer/releases/download/fork-latest/install.sh | sudo bash
```

This is the official Technitium installer with only the download URL changed. It points at the latest build of this fork. The script is generated by CI from `DnsServerApp/install.sh`.

- **Fresh machine:** it installs the ASP.NET Core runtime and ICU, and creates the `dns-server` user and the `dns` service, exactly like the official installer.
- **Machine already running Technitium:** it replaces the binaries and restarts the service. Settings in `/etc/dns`, including zones, scopes, the cluster and DHCP failover, are kept.
- **Pin a build:** pass the URL of a specific tarball, for example a CI artifact you host yourself:

  ```
  curl -sSL https://github.com/optimusprime-nn/DnsServer/releases/download/fork-latest/install.sh | sudo DNS_TAR_URL=https://example/DnsServerPortable.tar.gz bash
  ```

To go back to official Technitium, run the official installer. It installs over this fork the same way. One caveat: if you enabled Cluster auto failover or witness settings, the cluster config file is version 3, which official builds can't read. Leave the Cluster before switching back.

## Versions, rollback and updates

Fork builds are numbered **`<upstream version>.<CI run number>`**, for example `15.6.2.57`. That number is what the web console, the logs and the Cluster page show, so you can tell a fork build apart from official `15.6.2`, and one fork build from another. The assembly's informational version also carries the commit, for example `15.6.2.57+a1b2c3d`.

Every build is also kept as a numbered release `v15.6.2.N`, holding the last 20. Each one has its own `install.sh` that installs exactly that build. To roll back or pin a server, run:

```
curl -sSL https://github.com/optimusprime-nn/DnsServer/releases/download/v15.6.2.57/install.sh | sudo bash
```

The web console's **check for update** reads `update.json` from the `fork-latest` release instead of Technitium's servers. It reports when a newer fork build exists, and its link goes to that build's release page. It never offers the official download. These settings are applied by CI at build time; a plain local build still checks Technitium.

## Docker

```
docker pull ghcr.io/optimusprime-nn/dnsserver:fork-main
```

Images are built for amd64 and arm64 (Raspberry Pi 4/5). They are tagged with:

- the fork version (`15.6.2.57`), which never changes once published, so use it to pin a server;
- the branch name, which moves to every new build;
- `sha-<commit>`.

## Builds

GitHub Actions builds every push on the org's self-hosted runners; see `.github/workflows/build.yml`. Each push to `fork/main` replaces the [`fork-latest`](https://github.com/optimusprime-nn/DnsServer/releases/tag/fork-latest) pre-release with:

- `DnsServerPortable.tar.gz`
- `install.sh`
