# optimusprime-nn DnsServer fork

This fork of [Technitium DNS Server](https://github.com/TechnitiumSoftware/DnsServer) adds:

- redundant DHCP. See [DHCP-FAILOVER.md](DHCP-FAILOVER.md).
- cluster improvements, including 2-node auto failover. See [CLUSTER-IMPROVEMENTS.md](CLUSTER-IMPROVEMENTS.md).

## Install or update (Linux, systemd or OpenRC)

```
curl -sSL https://github.com/optimusprime-nn/DnsServer/releases/download/fork-latest/install.sh | sudo bash
```

This is the official Technitium installer with only the download URL changed. It points at the latest build of this fork. The script is generated by CI from `DnsServerApp/install.sh`.

- **Fresh machine:** it installs the ASP.NET Core runtime and ICU, and creates the `dns-server` user and the `dns` service, exactly like the official installer.
- **Machine already running Technitium:** it replaces the binaries and restarts the service. Settings in `/etc/dns`, including zones, scopes, the cluster and DHCP failover, are kept.
- **Pin a build:** pass the URL of a specific tarball, for example a CI artifact you host yourself:

  ```
  curl -sSL https://github.com/optimusprime-nn/DnsServer/releases/download/fork-latest/install.sh | sudo DNS_TAR_URL=https://example/DnsServerPortable.tar.gz bash
  ```

To go back to official Technitium, run the official installer. It installs over this fork the same way. One caveat: if you enabled Cluster auto failover or witness settings, the cluster config file is version 3, which official builds can't read. Leave the Cluster before switching back.

## Docker

```
docker pull ghcr.io/optimusprime-nn/dnsserver:feature-dhcp-failover
```

Images are built for amd64 and arm64 (Raspberry Pi 4/5).

## Builds

GitHub Actions builds every push on the org's self-hosted runners; see `.github/workflows/build.yml`. Each push to `feature/dhcp-failover` replaces the [`fork-latest`](https://github.com/optimusprime-nn/DnsServer/releases/tag/fork-latest) pre-release with:

- `DnsServerPortable.tar.gz`
- `install.sh`
